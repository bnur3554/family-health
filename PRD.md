# PRD — Семейное здоровье (Family Health)

**Версия документа:** 1.0
**Дата:** 2026-11-07
**Статус:** MVP (прототип v1.0) реализован и протестирован
**Владелец продукта:** Пользователь (семья)
**Платформа:** Мобильное веб-приложение (PWA), однофайловое — `family-health.html`

---

## 1. Видение продукта

Мобильное приложение для всей семьи (супруг/супруга, сын, дочь), которое объединяет контроль приёма витаминов, хранение и интерпретацию медицинских анализов, планирование питания и покупок — с учётом индивидуальных дефицитов каждого члена семьи.

**Ключевая ценность:** анализы → выявленные дефициты → автоматически влияют на меню и список покупок; приём витаминов → напоминания и отметки каждым членом семьи.

---

## 2. Проблема

- Витамины принимаются нерегулярно: у каждого члена семьи своё расписание, дозировка и дни — это сложно держать в голове.
- Результаты анализов лежат в PDF/бумажках, отклонения от нормы никто не отслеживает системно.
- Питание планируется без учёта реальных дефицитов (например, низкий витамин D у мамы не влияет на то, что семья покупает в магазине).
- Список покупок на неделю составляется вручную и отрывочно.

---

## 3. Цели продукта

| # | Цель | Метрика успеха |
|---|------|----------------|
| 1 | Регулярный приём витаминов всей семьёй | ≥ 80% отметок «принято» в неделю на члена семьи |
| 2 | Системный контроль анализов | Все анализы семьи хранятся в приложении, отклонения выявляются автоматически |
| 3 | Питание с учётом дефицитов | Меню на неделю генерируется за 1 нажатие и содержит продукты, закрывающие выявленные дефициты |
| 4 | Автоматизация покупок | Список покупок формируется из меню без ручного ввода |

**Не цели (Out of Scope для v1):** телемедицина, интеграция с клиниками и лабораториями, рецепты с граммовками и КБЖУ, носимые устройства, социальные функции.

---

## 4. Целевая аудитория

Семья из 4 человек (масштабируется на любое количество членов):

| Персона | Роль | Особенности |
|---------|------|-------------|
| Супруг(а) | Взрослый | Свои витамины, анализы; вероятно, администратор приложения |
| Супруг(а) | Взрослый | Свои витамины, анализы |
| Сын | Ребёнок | Детские нормы анализов (возрастные), витамины по расписанию |
| Дочь | Ребёнок | Детские нормы анализов (возрастные), витамины по расписанию |

**Важно:** нормы лабораторных показателей зависят от возраста и пола — приложение обязано учитывать оба параметра.

## 5. Принятые продуктовые решения (по результатам обсуждения)

| Вопрос | Решение |
|--------|---------|
| Платформа | **Мобильное приложение** — реализовано как мобильное веб-приложение (PWA-подход: устанавливается на домашний экран, адаптивная вёрстка под телефон) |
| Хранение данных | **Только локально** — все данные на устройстве (localStorage), без сервера. Максимальная приватность медицинских данных |
| Определение отклонений в анализах | **Оба варианта:** v1 — встроенная база референсных норм (офлайн, предсказуемо); ИИ-анализ документов — в roadmap |
| Приоритет | **Рабочий прототип сразу**, улучшения итерациями |

## 6. Функциональные требования

### 6.1. Профили семьи ✅ (реализовано в v1)

- Добавление/редактирование/удаление члена семьи.
- Атрибуты: имя, роль (Супруг(а), Сын, Дочь, Мама, Папа, Другое), возраст, пол, аватар (10 на выбор), цвет.
- На карточке профиля: количество назначенных витаминов, дата последнего анализа, прогресс приёмов за сегодня (например, 2/3).

### 6.2. Управление витаминами ✅

- Для каждого члена семьи — свой список витаминов/добавок.
- Атрибуты витамина: название (с подсказками: Витамин D3, C, B12, Омега-3, Магний, Железо и др.), дозировка, **несколько времён приёма в день** (8 готовых слотов + произвольное время), **дни недели** (например, пн/ср/пт).
- Редактирование и удаление.

### 6.3. Экран «Сегодня» и отметки приёма ✅

- Переключение между членами семьи (чипы с прогрессом каждого: «2/4 · 50%»).
- Расписание дня по времени: каждая строка — витамин, доза, время.
- **Отметка приёма одним нажатием** (toggle): «✓ принято» / «пропущено» (если время прошло более чем на 30 минут) / «нажми ✓».
- Прогресс-бар дня, состояние «Всё принято 🎉» при 100%.
- Тактильный отклик (вибрация) при отметке на мобильном.

### 6.4. Напоминания ✅

- Уведомления браузера (Notification API): в заданное время — «💊 {Имя}, время витаминов! {Название} · {доза} · {время}».
- Включаются кнопкой-колокольчиком в шапке (запрос разрешения).
- Проверка расписания каждые 30 секунд; напоминание приходит, только если приём ещё не отмечен; защита от дублей в рамках сессии.
- **Ограничение v1:** напоминания работают, пока приложение открыто (ограничение веб-платформы; для фоновых напоминаний — roadmap, Service Worker / нативная обёртка).

### 6.5. Анализы с определением отклонений ✅

**Ввод данных (два способа):**
1. **Вручную** — выбор показателя из базы, ввод значения (несколько показателей в одном анализе), дата анализа.
2. **Из документа** — загрузка файла (PDF/текст/CSV/фото): автоматическое распознавание показателей и значений по словарю алиасов (например, «гемоглобин», «HGB», «hemoglobin»), с последующей проверкой пользователем перед сохранением.

**База показателей v1 — 20 позиций** с нормами по возрасту и полу:
Гемоглобин, Ферритин, Витамин D (25-OH), Витамин B12, Фолиевая кислота, Кальций, Магний, Глюкоза, Холестерин общий, Железо сывороточное, ТТГ, Лейкоциты, Эритроциты, Тромбоциты, СОЭ, Общий белок, Калий, Цинк, Йод, Омега-3 индекс.

**Интерпретация:**
- Статус каждого показателя: `низкий ⬇` / `норма` / `высокий ⬆` — по референсному интервалу с учётом возраста и пола члена семьи.
- Для низких значений: рекомендации «🥗 Добавьте в рацион» (конкретные продукты) и «💊 Обсудите с врачом приём» (соответствующий витамин/добавка).
- Для высоких значений: рекомендуемые продукты/ограничения, где применимо.
- Обязательный дисклеймер: «Нормы справочные. Для интерпретации обратитесь к врачу».

**Хранение:** история анализов каждого члена семьи (все даты сохраняются; дефициты считаются по последнему анализу).

### 6.6. Меню на неделю ✅

- Генерация за 1 нажатие: 7 дней × 4 приёма пищи (завтрак, обед, перекус, ужин).
- **Учёт дефицитов семьи:** блюда, содержащие нутриенты, дефицитные у любого члена семьи, получают приоритет при выборе; такие блюда помечаются «⚡ нутриент».
- База блюд v1: 28 позиций (по 7 на приём пищи) с привязкой продуктов и нутриентов.
- Текущий день подсвечен в списке.
- Ротация блюд с элементом случайности (не повторяются подряд день за днём).

### 6.7. Список покупок ✅

- Формируется **автоматически** из сгенерированного меню + продукты из рекомендаций по отклонениям анализов.
- Группировка по категориям: Мясо и рыба, Молочные, Крупы и макароны, Овощи и зелень, Фрукты и ягоды, Орехи и семечки, Прочее.
- Отметки купленного (toggle), прогресс покупок, кнопка «Сбросить отметки (новая неделя)».
- Продукты, закрывающие дефициты, помечаются «⚡» с названием нутриента.

## 8. Техническая архитектура

- **Стек:** Vanilla HTML/CSS/JS, единый файл `family-health.html` (~915 строк). Без сборки, без внешних библиотек — переносится и открывается где угодно.
- **Хранилище:** `localStorage`, ключ `family_health_v1`.
- **Модель данных:**
  - `members[]` — { id, name, role, age, sex, avatar, color, vitamins[], labs[], intakes{} }
  - `vitamins[]` — { id, name, dose, times[], days[] }
  - `labs[]` — { id, date, results[{ testId, value, norm, status }] }
  - `intakes{}` — ключ `"YYYY-MM-DD|vitId|HH:MM"` → timestamp отметки
  - `menu` — { created, week[7]{ date, meals{ breakfast, lunch, snack, dinner } } }
  - `shopping` — { категория: [{ name, count, nutrients[], bought }] }
- **Справочники в коде:** `LAB_TESTS` (20 показателей: нормы как функция (возраст, пол), алиасы для распознавания, нутриент, продукты-рекомендации), `MEALS` (28 блюд), `CATEGORY` (категории покупок).
- **Качество:** 14 автоматических smoke-тестов логики (нормы, расписание, отметки, распознавание текста анализа, дефициты, генерация меню, список покупок, сохранение) — все пройдены ✅. Синтаксис JS проверен `node --check`.

## 9. Пользовательский интерфейс

**Навигация:** нижняя таб-панель (4 раздела): 🏠 Сегодня · 👨‍👩‍👧‍👦 Семья · 🧪 Анализы · 🍽 Меню. В шапке — логотип, дата и кнопка 🔔 (напоминания).

**Ключевые экраны:**
1. **Сегодня** — чипы членов семьи с прогрессом → прогресс-бар дня → список приёмов по времени (tap = отметить) → кнопки «＋ Витамин», «🧪 Анализы».
2. **Семья** — карточки членов семьи → детальный просмотр (витамины) → модалки добавления/редактирования.
3. **Анализы** — чипы членов семьи → список анализов по датам с чипами «N отклонений» / «Всё в норме ✓» → карточки отклонений с рекомендациями.
4. **Меню** — блок дефицитов семьи → карточки 7 дней → список покупок по категориям с прогрессом.

**Дизайн-система:** тёмная тема, акцент #22c39a (мятный), семантические цвета: зелёный = норма/принято, жёлтый = отклонение/внимание, красный = критично/удаление, синий = информация. Модальные окна — bottom sheet (выезжают снизу), радиус 12–16px, анимации появления.

## 11. Roadmap (после MVP)

| Приоритет | Функция | Описание |
|-----------|---------|----------|
| P1 | Синхронизация между устройствами семьи | Общий бэкенд (Supabase/Firebase) или экспорт/импорт JSON — чтобы каждый отмечал приём со своего телефона |
| P1 | ИИ-анализ анализов (Claude API) | Загрузка фото/PDF анализа → ИИ распознаёт и интерпретирует любой формат лаборатории; краткая сводка простым языком |
| P2 | Фоновые напоминания | Service Worker + Push API либо нативная обёртка (Capacitor) — напоминания при закрытом приложении |
| P2 | Графики динамики показателей | История анализов по датам → графики (например, витамин D за год) |
| P3 | Экспорт/резервное копирование | Выгрузка всех данных в JSON, восстановление |
| P3 | Курсы приёма витаминов | Дата начала/окончания курса, напоминание «курс заканчивается — купить?» |
| P3 | Расширение базы | Больше показателей анализов и блюд; настройка норм вручную; учёт аллергий и предпочтений в меню |
| P4 | Нативное приложение | Упаковка PWA в Android/iOS (Capacitor) для публикации в сторах |

## 12. Открытые вопросы

1. Нужна ли защита PIN-кодом (медицинские данные детей)?
2. Как делиться данными между устройствами до появления сервера — достаточно ли экспорта/импорта JSON?
3. Какой формат больничных анализов у семьи чаще всего (PDF из лаборатории, фото бланка) — влияет на приоритет ИИ-распознавания.
4. Нужны ли дозировки витаминов по нормам (суточные нормы по возрасту) или оставить произвольный ввод, назначенный врачом?

## 13. Ограничения и дисклеймеры

- Приложение **не является медицинским изделием** и не ставит диагнозы. Референсные нормы носят справочный характер; интерпретацию анализов и назначение витаминов/дозировок выполняет только врач.
- Напоминания v1 работают при открытом приложении.
- Данные хранятся локально: очистка данных браузера удалит их (см. roadmap — резервное копирование).
